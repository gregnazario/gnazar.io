# Dependency Security Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade all direct Bun dependencies, remediate audit findings with compatible targeted overrides, and correct verified application incompatibilities.

**Architecture:** The existing updated manifest and lockfile are the starting point. Bun resolves current versions first; remaining vulnerabilities are traced to their parent dependency and fixed with upstream upgrades or constrained `overrides`. Compatibility fixes stay at the affected configuration or application boundary and are validated by the existing test/build suite.

**Tech Stack:** Bun 1.3, React 19, TanStack Start/Router, Vite 8, TypeScript 7, Vitest 4, Playwright, Biome, Netlify Vite plugin.

---

## File structure

- Modify: `package.json` — direct dependency versions and audit-driven `overrides`.
- Modify: `bun.lock` — deterministic resolved package graph generated by Bun.
- Modify only when validation identifies a breaking change: affected file in `src/`, `scripts/`, `vite.config.ts`, or test files.
- Create: `docs/superpowers/specs/2026-08-19-dependency-security-upgrade-design.md` — approved design record (already created).
- Create: `docs/superpowers/plans/2026-08-19-dependency-security-upgrade.md` — this execution plan.

### Task 1: Establish the post-upgrade audit baseline

**Files:**
- Modify: `package.json`
- Modify: `bun.lock`

- [ ] **Step 1: Inspect the current user dependency changes without overwriting them**

Run:

```bash
git status --short
git diff -- package.json bun.lock
```

Expected: the existing direct-version updates remain visible; unrelated `.gitignore` and `content/templates/` work is not touched.

- [ ] **Step 2: Resolve the manifest with Bun**

Run:

```bash
bun install
```

Expected: Bun updates `bun.lock` from the existing `package.json` without changing unrelated files.

- [ ] **Step 3: Record the remaining vulnerable package paths**

Run:

```bash
bun audit
```

Expected: a report mapping each remaining vulnerable package to its direct/transitive parent path.

- [ ] **Step 4: Commit the dependency baseline**

```bash
git add package.json bun.lock
git commit -m "deps: update direct dependencies"
```

Expected: commit contains only manifest and lockfile dependency-resolution changes. Do not commit unrelated existing changes.

### Task 2: Remediate residual transitive audit findings

**Files:**
- Modify: `package.json`
- Modify: `bun.lock`

- [ ] **Step 1: Group audit findings by immediate parent and safe fixed version**

Run:

```bash
bun audit
```

Expected: each unresolved finding is assigned to an upstream parent package; findings already removed are not overridden.

- [ ] **Step 2: Add exact safe overrides only for remaining vulnerable transitives**

In `package.json`, add an `overrides` object only if the audit still reports vulnerable packages. Use the audit’s minimum fixed release, preserving JSON formatting. For example, if a path permits it:

```json
{
  "overrides": {
    "rollup": "4.59.0",
    "yaml": "2.8.3"
  }
}
```

Do not add either illustrative override unless the current audit reports it and the selected version satisfies its parent dependency range.

- [ ] **Step 3: Regenerate the lockfile and verify resolution**

Run:

```bash
bun install
bun audit
```

Expected: the overridden versions appear in `bun.lock`; audit findings are reduced or eliminated without peer-dependency resolution errors.

- [ ] **Step 4: Commit the audit remediation**

```bash
git add package.json bun.lock
git commit -m "deps: remediate transitive audit findings"
```

Expected: commit contains only audit-driven overrides and their resolved lockfile changes.

### Task 3: Fix proven compatibility regressions with tests first

**Files:**
- Modify: the exact failing source/configuration file reported by validation
- Modify: the closest existing `*.test.ts` or `*.test.tsx` file for behavior changes

- [ ] **Step 1: Run the typecheck and unit suite to identify concrete failures**

Run:

```bash
bun run build
bun run test:run
```

Expected: either both pass or output identifies a specific incompatibility introduced by the upgrades.

- [ ] **Step 2: Write one focused failing regression test for each application behavior failure**

For a failure in an existing component or utility, add a test using the project’s Vitest and Testing Library style. The test must state observable behavior and fail before the source fix. Example pattern:

```ts
it("renders the supplied heading", () => {
  render(<Component heading="Updated heading" />);

  expect(screen.getByRole("heading", { name: "Updated heading" })).toBeInTheDocument();
});
```

Run:

```bash
bun run test:run -- path/to/affected.test.tsx
```

Expected: FAIL due to the verified upgrade regression, not due to test setup or syntax.

- [ ] **Step 3: Make the narrowest source or configuration correction**

Implement only the API/configuration change required by the failing test or build error. Do not refactor unrelated code.

- [ ] **Step 4: Verify the regression and full unit suite**

Run:

```bash
bun run test:run -- path/to/affected.test.tsx
bun run test:run
bun run build
```

Expected: the regression test, all unit tests, and the production build pass.

- [ ] **Step 5: Commit each isolated compatibility correction**

```bash
git add path/to/affected-source.tsx path/to/affected.test.tsx
git commit -m "fix: adapt to dependency upgrade"
```

Expected: source and regression test are committed together. Skip this task’s commit if no compatibility correction is needed.

### Task 4: Run full project validation and final audit

**Files:**
- Modify: `package.json` and `bun.lock` only if final audit remediation is still necessary

- [ ] **Step 1: Check formatting and linting**

Run:

```bash
bun run format:check
bun run lint
```

Expected: zero formatting and lint errors.

- [ ] **Step 2: Run end-to-end and content validation**

Run:

```bash
bun run test:e2e
bun run validate
```

Expected: Playwright suite and content/link validation pass. If browsers are absent, install them only through the project’s Playwright workflow, then rerun.

- [ ] **Step 3: Run final audit**

Run:

```bash
bun audit
```

Expected: zero audit advisories. If one remains because no compatible fixed version exists, report its advisory, package path, fixed-version availability, and why an override is unsafe.

- [ ] **Step 4: Scan modified code and report results**

Run the project’s configured security scanner against every source/configuration file modified for compatibility; rescan after remediating any finding.

Expected: no introduced SAST issues or exposed secrets.

- [ ] **Step 5: Commit final dependency validation changes**

```bash
git add package.json bun.lock
git commit -m "deps: finalize secure dependency resolution"
```

Expected: only commit if Task 4 changes the dependency files; never include unrelated worktree files.
